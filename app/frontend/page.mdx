### Key Conceptual Frameworks

#### 1. React Server Components (RSC) vs Client Components

- **Server Components:** Execute exclusively on the server at request or build time. Zero client-side JavaScript bundle footprint. Direct database/backend access with streaming HTML.
- **Client Components:** Hydrated on the browser to attach event listeners, browser APIs, and state (`useState`, `useEffect`, `useReducer`). Indicated with the `'use client'` boundary.

#### 2. Critical Rendering Path

```
DOM Construction -> CSSOM Construction -> Render Tree -> Layout (Reflow) -> Paint -> Compositing
```

- **Layout Thrashing:** Avoid interleaving style/layout reads (e.g. `offsetHeight`) with DOM writes to eliminate forced synchronous layouts.
- **Resource Prioritization:** Optimize LCP with high-priority image fetching (`priority`), preload fonts, and defer non-critical scripts.

### Architectural Patterns

- **Compound Components:** Flexible component composition sharing implicit state via React Context (e.g., `<Select><Select.Option /></Select>`).
- **State Machines & Store Design:** Isolating complex transition logic from presentation components using finite state machines or immutable state stores.
- **Micro-Frontends & Module Federation:** Decoupling large enterprise codebases into independently deployable units while sharing common dependencies.
